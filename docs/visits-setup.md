# 来院分析（新患・お久しぶり患者の抽出）導入・運用手順

予約表のデータから **新規患者** と **お久しぶりの患者（前回来院から90日以上）** を抽出し、月次集計を作るツール。

- 姿勢評価（LIFF）システムとは **完全に別物**。LINE・既存 GAS・既存シートとは一切つながっていない。
- 新しいスプレッドシート1つと、そこに入れる Apps Script だけで動く。外部への送信は無い。
- 予約表そのものには触らない。予約表の行を **コピーして貼り付けたデータ** だけを読む（接続なし版）。

コード: `visits/`

## 1. 導入（初回のみ・約10分）

1. Google ドライブで **新しいスプレッドシート** を作成する（名前例: `来院分析`）。
   院の管理者のみアクセスできる場所に置く（氏名を含むため共有範囲に注意）。
2. メニュー **拡張機能 → Apps Script** を開く。
3. 最初からある `コード.gs` を削除し、`visits/` の次の5ファイルを同名で作成して中身を貼り付ける。
   - `Classifier.gs` / `Config.gs` / `Reader.gs` / `Report.gs` / `Menu.gs`
4. 左の歯車（プロジェクトの設定）→「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` を `visits/appsscript.json` の内容に置き換える。
5. 保存し、スプレッドシートを再読み込みする。上部に **「来院分析」メニュー** が出る。
6. **来院分析 → 初期設定（シート作成）** を実行する（初回は権限の承認画面が出るので許可する）。
   `予約データ` と `設定` シートが作られる。

## 2. 使い方（毎回）

1. 予約表を開き、**見出し行を含めて** 必要な範囲をコピーする（過去分も含めて全部が理想）。
2. `予約データ` シートの A1 に貼り付ける（前回分は上書きしてよい）。
3. **来院分析 → 今すぐ集計** を実行する。

> 過去分が多いほど判定が正確になる。「新患」は *貼り付けたデータの中で初めて出てきた* 来院、という意味なので、
> 直近分だけ貼ると以前から通っている患者も新患に見えてしまう（→ 下記「新患（要確認）」）。

## 3. 設定シート

予約表の見出し名が既定値と違う場合は、`設定` シートの **B列** を予約表の見出しに合わせて書き換える。

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| 日付の列 | 日付 | 必須。`2026/9/28`・`2026-09-28`・`2026年9月28日`・日付セルに対応 |
| 患者IDの列 | 診察券番号 | 必須。全角/半角・先頭ゼロの違いは同一視する（`01007` と `1007` は同じ患者） |
| 氏名の列 | 氏名 | 任意 |
| 担当の列 | 担当 | 任意。担当者別集計に使う |
| メニューの列 | メニュー | 任意 |
| 状態の列 | 状態 | 任意。キャンセル判定に使う |
| キャンセル扱いの文言 | キャンセル,取消,無断 | 状態の列にこの文言を **含む** 行は来院に数えない |
| お久しぶり判定日数 | 90 | 前回来院からこの日数以上空いたら「お久しぶり」 |

見出しに無い余分な列（時間など）はあっても問題ない。

## 4. 判定ルール

| 区分 | 条件 |
| --- | --- |
| 新患 | その患者IDの最初の来院 |
| 新患（要確認） | 新患のうち、データの最古日から90日以内の来院。データ開始より前から通っていた可能性があるため別集計にする |
| お久しぶり | 前回来院から90日以上空いた来院 |
| 継続 | 上記以外 |

- キャンセル行・患者ID空欄の行・日付が読めない行は除外（件数は集計結果と `実行ログ` に表示）。
- 同じ患者の同日の予約が複数あっても1来院として数える。
- 毎回すべて計算し直すので、予約表の修正（キャンセルへの変更など）は貼り直して再集計すれば反映される。

## 5. 出力シート

| シート | 内容 |
| --- | --- |
| 抽出リスト | 新患・お久しぶりの来院のみ（新しい順）: 来院日 / 患者ID / 氏名 / 区分 / 前回来院日 / 空白日数 / 担当 / メニュー |
| 来院ログ | 全来院に区分を付けたもの（検算・ピボットテーブル用） |
| 月次集計 | 月ごと: 延べ来院数 / 実患者数 / 新患 / 新患(要確認) / お久しぶり / 継続 / 新患率 / お久しぶり率 ＋ 推移グラフ |
| 担当者別 | 月×担当者ごとの 延べ来院数 / 新患 / 新患(要確認) / お久しぶり |
| 実行ログ | 実行日時・件数・除外件数・エラー内容 |

率はいずれも「その月の実患者数」に対する割合。

## 6. 毎日自動実行（任意）

**来院分析 → 毎日自動実行をON** で、毎朝5時台に自動で集計し直す。
接続なし版では「貼り付け済みデータの再集計」になるだけなので、通常は手動の「今すぐ集計」で十分。
（将来、予約表に直接接続する場合に活用する。）

## 7. 動作確認用サンプル

`visits/sample/reservations-sample.csv` はダミーの予約データ（架空の患者）。
`予約データ` シートで **ファイル → インポート → 現在のシートを置換** で読み込み、集計すると
「来院16件 / 新患4件（要確認4件）/ お久しぶり4件 / キャンセル除外2件 / ID空欄1件」になる。

開発者向け: `node visits/test/classifier.test.js` と `node visits/test/report.test.js` でロジックを検証できる。

## 8. よくあるエラー

| メッセージ | 対処 |
| --- | --- |
| 見出し「〇〇」が見つかりません | `設定` の列名を予約データ1行目の見出しと同じ文字にする（前後の空白は無視される） |
| 日付不正除外 が多い | 日付の列に年が無い（`9/28` のみ）など。予約表側で年付きの日付にする |
| 別の集計が実行中です | 数十秒待って再実行 |
