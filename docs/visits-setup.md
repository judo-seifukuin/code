# 来院分析（新患・お久しぶり患者の抽出）導入・運用手順

Google ドライブ上の予約表（名前に `/Res/` を含むスプレッドシート）を読み、
**新規患者** と **お久しぶりの患者（前回来院から90日以上）** を抽出して、院別・月別に集計するツール。

- 姿勢評価（LIFF）システムとは **完全に別物**。LINE・既存 GAS・既存シートとは一切つながっていない。
- 新しいスプレッドシート1つと、そこに入れる Apps Script だけで動く。
- 予約表は **読むだけ**。予約表を書き換えることは一切ない。
- 結果には患者の氏名が入るため、来院分析スプレッドシートは院の管理者だけが見られる場所に置くこと。

コード: `visits/`

## 1. 導入（初回のみ・約10分）

1. 予約表を見られる Google アカウントで、ドライブに **新しいスプレッドシート** を作成する（名前例: `来院分析`）。
2. メニュー **拡張機能 → Apps Script** を開く。
3. 最初からある `コード.gs` を削除し、`visits/` の次の7ファイルを同名で作成して中身を貼り付ける。
   - `Classifier.gs` / `GridReader.gs` / `Config.gs` / `Reader.gs` / `Source.gs` / `Report.gs` / `Menu.gs`
4. 左の歯車（プロジェクトの設定）→「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` を `visits/appsscript.json` の内容に置き換える（Sheets API の有効化もこれで行われる）。
5. 保存し、スプレッドシートを再読み込みする。上部に **「来院分析」メニュー** が出る。
6. **来院分析 → 初期設定** を実行する。初回は権限の承認画面が出るので許可する
   （ドライブは「閲覧のみ」の権限。予約表を探して読むために使う）。
   `設定` と `ファイル一覧` シートが作られる。
7. `ファイル一覧` を確認し、集計に使うファイルにチェックが入っていることを確認する。
8. **来院分析 → 今すぐ集計**。初回は全ファイルを読むので数分かかる。

> 初回に「時間内に読み切れなかったファイルがあります」と出たら、もう一度「今すぐ集計」を押す（続きから読む）。

## 2. 使い方

| メニュー | 内容 |
| --- | --- |
| 今すぐ集計（更新分のみ読込） | 前回から更新された予約表だけ読み直して集計する。普段はこれ |
| 全ファイルを読み直して集計 | 対象の予約表をすべて読み直す。設定を変えたとき・結果がおかしいとき |
| 予約表ファイルを検索 | ドライブを検索し直して `ファイル一覧` を更新する（新しい月のファイルを追加） |
| 毎日自動実行をON / OFF | 毎朝5時台に「検索 → 更新分の集計」を自動で行う |

## 3. ファイル一覧

ドライブの中で名前に `/Res/` を含むスプレッドシートを一覧にしたもの。

- 名前が `年.月/Res/院名`（例 `2026.9/Res/桜台`、複数月は `2026.9.10.11/Res/桜台`）のものが対象。
- `原本/…`・`修正版`・`【使用禁止】` は自動で対象外（メモに理由）。
- 同じ院・同じ月のファイルが複数ある場合はメモで知らせる。両方読んでも同じ日の同じ番号は1来院にまとまるが、
  古いコピーなど不要なものはチェックを外す。
- チェック状態は「予約表ファイルを検索」をし直しても保持される。

## 4. 予約表の読み方

各ファイルの日タブ（`09-01（火）` のような名前のタブ）だけを読む。`テンプレ`・`顧客リスト`・`予約ログ` などのタブや、
前の月の残りのタブ（9月ファイル内の `01-31(土)` など）は読まない。

日タブの中は、担当者ごとの `NO | 名前 | 時間 | 備考` の列を見出し行から見つけて読む。

- **NO** = 診察券番号、**担当** = そのブロックの上の担当者名、**時刻** = B列。
- 名前が `-` の空き枠は読まない。「これ以上は絶対に入れないこと」の行より下は読まない。
- 読んだ予約は `予約明細` シートに1枠1行で保存される（検算用）。

## 5. 判定ルール

| 区分 | 条件 |
| --- | --- |
| 新患 | その院でその番号が初めて出てきた来院 |
| 新患（要確認） | 新患のうち、その院のデータの最古日から90日以内の来院。それ以前から通っていた可能性があるため別集計 |
| 新患（番号未発行） | 仮番号（既定 `990`）での来院。番号で人を追えないため、同じ日の同じ備考（〇〇さん）を1来院として数える |
| お久しぶり | 前回来院から90日以上空いた来院 |
| 継続 | 上記以外 |

- 同じ患者の同じ日の予約（40分枠で2行に分かれている等）は1来院。
- 備考にキャンセル扱いの文言を含む枠は数えない。
- 毎回すべて計算し直すので、予約表の修正も次の集計で反映される。

## 6. 設定シート

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| お久しぶり判定日数 | 90 | 前回来院からこの日数以上空いたら「お久しぶり」 |
| キャンセル扱いの文言 | キャンセル,取消,無断 | 備考にこの文言を含む枠は来院に数えない |
| 仮番号 | 990 | 番号未発行の新患に使う仮の番号（カンマ区切りで複数可） |
| 院名の別名 | 東村=東村山 | ファイル名の院名の表記ゆれをまとめる（`別名=正式名`、カンマ区切り） |
| 番号を全院共通として扱う | いいえ | 「はい」にすると、別の院でも同じ番号は同じ患者とみなす |
| 日付の列 など【貼り付けデータ用】 | | 下記「予約表以外の来院を足す」用 |

設定を変えたら **全ファイルを読み直して集計** を実行する。

## 7. 出力シート

| シート | 内容 |
| --- | --- |
| 抽出リスト | 新患・お久しぶりの来院のみ（新しい順）: 院 / 来院日 / 患者ID / 氏名 / 区分 / 前回来院日 / 空白日数 / 担当 / 備考 |
| 来院ログ | 全来院に区分を付けたもの（ピボットテーブル用） |
| 月次集計 | 院×月: 延べ来院数 / 実患者数 / 新患 / 新患(要確認) / 新患(番号未発行) / お久しぶり / 継続 / 新患率 / お久しぶり率。院が複数なら先頭に「全院」行。全院（院が1つならその院）の推移グラフ付き |
| 担当者別 | 院×月×担当: 延べ来院数 / 新患 / 新患(要確認) / 新患(番号未発行) / お久しぶり |
| 予約明細 | 予約表から読み込んだ全予約枠 |
| 実行ログ | 実行日時・読込ファイル数・件数・除外件数・エラー内容 |

率はいずれも「その月の実患者数」に対する割合。

## 8. 予約表以外の来院を足す（任意）

このスプレッドシートに `予約データ` という名前のシートを作り、1行目に見出し（`日付` `診察券番号` `氏名` `担当` `状態` `院`）、
2行目以降に1行1来院で貼り付けると、その分も合わせて集計される。見出し名は設定シートの【貼り付けデータ用】で変えられる。

## 9. よくある質問・エラー

| 症状 | 対処 |
| --- | --- |
| 「ファイル一覧がありません」 | メニュー「予約表ファイルを検索」を実行する |
| ファイル一覧に予約表が出てこない | 予約表の名前が `年.月/Res/院名` になっているか、このアカウントで予約表を開けるかを確認 |
| 新患（要確認）が多い | データの最初の3か月はそうなる。過去の予約表（古い月のファイル）もドライブにあれば自動で対象になる |
| 別の処理が実行中です | 数十秒待って再実行 |

開発者向け: `node visits/test/classifier.test.js`・`node visits/test/gridreader.test.js`・`node visits/test/report.test.js` でロジックを検証できる（予約表はテスト内のダミー）。
